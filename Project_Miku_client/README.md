# Project Miku Client

Live2D 데스크톱 AI 어시스턴트용 가벼운 클라이언트 (Electron + pixi-live2d-display).
VTube Studio 모델 폴더(`*.vtube.json` + `*.model3.json`)를 그대로 넣어 쓸 수 있게 만든 뼈대입니다.

## 실행

```bash
npm install
# vendor/ 에는 Live2D Cubism Core 가 이미 들어 있어요 (아래 참고)
npm start
```

### Cubism Core
pixi-live2d-display(Cubism 4)는 Live2D 공식 Core 라이브러리가 필요해서, `vendor/live2dcubismcore.min.js` 를 함께 넣어 두었어요.
이 파일은 Live2D Inc. 의 "Redistributable Code" 이고 [Live2D Proprietary Software License Agreement](https://www.live2d.com/eula/live2d-proprietary-software-license-agreement_en.html) 를 따릅니다 (파일 맨 위의 저작권/라이선스 주석을 지우지 마세요). 자세한 내용은 저장소의 `THIRD_PARTY_NOTICES.md` 를 보세요.
파일이 없거나 새 버전이 필요하면 Live2D 사이트의 Cubism SDK for Web 에서 `live2dcubismcore.min.js` 를 받아 `vendor/` 에 넣으세요.

## 모델 추가

`models/<모델이름>/` 폴더에 VTube Studio 모델 폴더 내용을 그대로 복사합니다.

- `*.vtube.json` 이 있으면 핫키(표정/모션), 대기 모션을 읽어 감정 맵을 자동 구성
- `*.vtube.json` 의 **아트메시 색/투명도**(VTube Studio 에서 워터마크 등을 투명하게 만든 설정)를 그대로 적용합니다. 투명도(곱하기 색의 알파)는 항상 적용되고, 색 틴트는 렌더러가 지원할 때만 보입니다. 모델을 불러올 때 `miku.log` 에 `[artmesh] ... N개 중 M개 적용` 줄이 남고, 설정 창 "화면/앱" 탭의 "VTube Studio 아트메시 투명도/색 적용"으로 끌 수 있습니다
- `*.vtube.json` 이 없으면 `model3.json` 에 등록된 표정 이름으로 폴백
- 트레이 메뉴 → 모델 에서 선택 / 목록 새로고침

모델 폴더 안(하위 폴더 2단계까지)에 `*.vtube.json` 또는 `*.model3.json` 이 있으면 인식됩니다.

## 감정 연결: 표정 파일 이름이 곧 감정 태그

서버가 보내는 감정 라벨은 `neutral`, `happy`, `sad`, `angry`, `surprise` 입니다.
모델 폴더(하위 폴더 포함)에 **라벨과 같은 이름의 표정 파일**이 있으면 자동으로 연결됩니다. config 수정 불필요.

```
models/내모델/
  happy.exp3.json      <- 서버 happy 감정에 연결
  sad.exp3.json
  angry.exp3.json
  surprise.exp3.json
  wave.motion3.json    <- 모션도 이름으로 연결 (같은 이름이면 표정 우선)
```

- 동의어도 인식: happy = joy/smile/기쁨/행복, sad = 슬픔/cry, angry = anger/분노, surprise = 놀람/shock, neutral = default/중립
- 파일 이름을 바꿔도 안전: `model3.json` 이 옛 이름을 가리켜도 디스크에 없는 참조는 자동으로 무시
- 우선순위: 모델 폴더의 `emotionAliases.json` > 파일 이름 > VTS 핫키 이름 > `model3.json` 표정 이름 (아래 "모델별 persona / 감정 태그")
- 확인: 모델에 마우스를 올려 입력창을 띄우고 `/emo` (이름 목록), `/emo happy` (미리보기)

## 모델별 persona / 감정 태그

모델마다 캐릭터 설정과 감정 태그↔표정 연결을 따로 관리합니다. 파일은 **모델 폴더 안**에 있어서 모델을 옮기면 같이 갑니다.

```
models/내모델/
  persona.txt           <- 이 모델의 캐릭터 설정 (없으면 서버의 persona.txt 사용)
  emotionAliases.json   <- 감정 태그 -> 표정
  voice.json            <- 이 모델의 GPT-SoVITS 음성 (가중치, 참조 음성). 없으면 서버 설정을 사용
```

`emotionAliases.json` (값은 표정 파일 이름, 또는 설명을 붙인 `{expression, desc}`):

```json
{
  "neutral": "default.exp3.json",
  "happy":   { "expression": "Fanged Smile.exp3.json", "desc": "기쁨, 즐거움" },
  "smirk":   { "expression": "Yandere.exp3.json", "desc": "집착, 조롱" }
}
```

- **키(태그)가 곧 AI 가 고르는 감정 목록**이 됩니다 (서버가 프롬프트에 넣음). 모델에 실제로 연결되는 태그만 보내므로, 표정이 안 나오는 태그를 AI 가 고르지 않습니다. 쓸 수 있는 태그가 없으면 서버 기본 감정을 씁니다. 태그는 영어/한글 글자만 (최대 20자, 24개).
- `desc` 는 AI 에게 주는 힌트 (생략 가능, 생략하면 happy/sad 같은 기본 태그는 기본 설명 사용).
- **설정 창 > 모델 탭**에서 지금 모델의 persona 와 감정 표를 고칩니다 (표정은 모델의 표정 목록에서 고르고 ▶ 로 미리보기). 저장하면 파일에 쓰고 서버에도 바로 알립니다. 서버를 다시 켜거나 모델을 바꿔도 클라이언트가 자동으로 다시 보냅니다.
- 설정 창의 그룹 제목(예: 화면, 시선, 음성)을 누르면 그 그룹이 접히고 펼쳐집니다. 접어 둔 상태는 기억해 둡니다.
- 파일을 직접 고쳐도 됩니다. 이 경우 모델을 다시 불러와야(트레이 > 모델) 반영됩니다.
- **옛 설정 이전**: `emotionAliases.json` 이 아직 없는 모델은 처음 불러올 때 `config.json` 의 `emotionAliases` + `modelAliases[모델]` 을 그 파일로 한 번 옮겨 줍니다. 그 뒤로는 파일만 읽으니 `config.json` 쪽은 지워도 됩니다.
- persona 를 비우고 저장하면 `persona.txt` 가 지워지고 서버 기본을 씁니다.
- **음성(GPT-SoVITS)**: 설정 창 > 모델 탭의 "음성" 칸(GPT 가중치, SoVITS 가중치, 참조 음성 파일/대사/언어, 말하는 속도)에 적으면 `voice.json` 에 저장되고 서버에 바로 알립니다. 서버 PC 기준 경로이고, 비워 둔 칸은 서버 설정의 값을 씁니다. `voice.json` 의 `speed_factor`(0.5~2.0, 1.0=보통, 숫자)는 말하는 속도로, GPT-SoVITS 는 `speed_factor`, Edge TTS 는 `rate`(예: 1.2 → +20%)로 반영됩니다 (비우면 서버 설정). 모두 비우고 저장하면 `voice.json` 이 지워집니다. 가중치 동작은 서버 README 의 "GPT-SoVITS 가중치" 참고 (모델마다 다르게 쓰려면 서버 설정 탭에 기본 가중치를 적어 두세요).

## 감정 연결 (2): `<think>` 내용 기반

서버가 모델의 `[감정]*lowers head, cheeks turning slightly red*대사` 응답에서 행동 묘사를 분리해 `<think>*lowers head, cheeks turning slightly red*</think>본문` 형태로 보내 줍니다 (서버 README "응답 형식과 파싱"). 이 경우,
`<think>` 안의 문장에서 표정 단서(blush/red, smile, sad, 웃/슬/놀 …)를 찾아 **모델에 있는 표정 이름**과 매칭합니다.

- `<think>` 는 말풍선 본문에서 분리되어 위쪽 작은 글씨로 표시: `💭 …` / `감정: red → 표정:red (think)`
- think 에 단서가 없으면 서버 감정 라벨로 폴백 (`서버 라벨, think 단서 없음`)
- 별칭 값에 파일 이름을 그대로 써도 됨: `"happy": "smirk.exp3.json"` (확장자/경로는 자동 제거)
- 테스트: `/emo think *smiles brightly*` → 어떤 표정이 선택되는지 미리보기
- 끄려면 `"showThink": false` (think 줄 숨김), `"showEmotionTag": false` (감정 줄 숨김)

## 조작

창이 **화면 작업 영역 전체**를 투명하게 덮고, 모델이 그 안에서 자유롭게 움직입니다. 모델/말풍선/입력창이 아닌 곳은 클릭이 뒤로 통과됩니다.

- 모델 위에 마우스를 올리면 입력창이 나타나고, **이미 사라진 마지막 대사창도 다시 보임** (마우스를 올려 둔 동안은 유지, 벗어나면 숨음. 안내/오류 메시지는 다시 보이지 않고 캐릭터의 대사만. 설정의 대사창 끄기를 켜 두면 안 보임). Enter 전송, Esc 닫기. 입력창을 한 번 클릭해야 글자를 칠 수 있음
- **모델 우클릭** 또는 트레이 아이콘 클릭: 아래 메뉴 표시
- 말하는 도중 새 메시지를 보내면 **기존 음성을 끊고** 새 응답을 말함. 서버가 먼저 거는 말(observe/알림)은 끊지 않고 이어서 말함
- 말풍선은 음성이 끝난 뒤 `bubbleSeconds`(기본 6초) 뒤에 사라짐
- 입력창에 `/emo` (사용 가능한 이름 목록), `/emo happy` (표정 미리보기). 서버로 보내지 않는 로컬 명령

메뉴:

| 메뉴 | 설명 |
|---|---|
| 모델 / 모델 목록 새로고침 | 모델 전환 |
| 모니터 | 모니터가 2개 이상일 때만 표시. 모델을 띄울 화면 선택 |
| 모델 표시 (Ctrl+Alt+H) | 모델 숨기기/표시. 숨겨도 서버 통신과 음성은 계속됨 |
| 편집 모드 | 아래 참고 |
| 투명 영역 클릭 통과 | 모델 **주변의 빈 부분**만 클릭이 뒤로 통과. 모델 몸통은 마우스를 받음 |
| 모델 뒤 클릭 가능 (Ctrl+Alt+P) | 모델 **몸통까지** 전부 통과. 모델에 가려진 창도 클릭 가능. 켜면 입력창/드래그는 못 쓰니 단축키로 다시 끄세요 |

단축키는 `config.json` 의 `hotkeys` 로 바꿀 수 있음: `{"hotkeys": {"toggleModel": "Ctrl+Alt+H", "toggleClickThrough": "Ctrl+Alt+P"}}`

### 편집 모드

별도의 틀 없이, 모델을 화면 어디로든 끌어서 옮깁니다. 값은 자동 저장됨.

- 모델 드래그: 위치 이동 / 모델 위에서 마우스 휠: 크기 조절
- 말풍선+입력창 상자(파란 점선) 드래그: 위치 이동
- 모델 옆 패널: 모델 크기, 입력창 너비, 글자 크기 슬라이더, 초기화
- 편집 중에도 빈 화면은 클릭이 통과되므로 바탕화면을 그대로 쓸 수 있음
- 패널의 [완료] 또는 메뉴에서 다시 눌러 종료

## 대화(세션) 관리

웹 LLM 처럼 대화를 나눠서 관리합니다. **서버를 켤 때마다 새 대화**로 시작하고, 첫 메시지를 보내면 목록에 저장됩니다. 대화마다 기록이 따로라 문맥이 섞이지 않습니다.

- **열기**: `Ctrl+Alt+S`, 입력창 오른쪽의 **☰ 버튼**, 또는 트레이/우클릭 메뉴의 "대화 목록". 닫기는 `Esc` 또는 ✕
- **＋ 새 대화** (트레이의 "새 대화 시작"도 같음): 지금 대화는 목록에 그대로 남고, 다음 메시지부터 새 대화로 저장됩니다
- 목록에서 대화를 **클릭하면 그 대화로 전환**됩니다. 아래쪽에 지금 대화의 **기록**이 보입니다
- **✎ 이름 바꾸기**: Enter 확정, Esc 취소. **🗑 삭제**: 한 번 누르면 "삭제?"로 바뀌고, 3초 안에 한 번 더 누르면 지웁니다. 삭제하면 그 대화의 기록도 완전히 사라집니다
- **🔍 검색**: 패널 위쪽 검색 상자에 입력하면 대화 제목과 내용에서 찾아 줍니다. 결과를 누르면 그 대화로 전환됩니다. Esc 로 지웁니다
- **⬇ 내보내기**: `⬇ 이 대화` / `⬇ 전체` 버튼으로 대화를 글 파일(`.md`)로 저장합니다. 저장 위치는 물어봅니다
- **전체 삭제**: 한 번 누르면 "정말 전부?"로 바뀌고, 3초 안에 한 번 더 누르면 모든 대화를 지웁니다 (장기 기억은 남습니다)
- 입력창 안내문에 지금 대화 이름이 표시됩니다
- 단축키는 `config.json` 의 `hotkeys.toggleSessions` 로 바꿀 수 있습니다

## 먼저 말 걸기 (캐릭터가 스스로 말을 거는 모드)

사용자가 한동안 말이 없으면 캐릭터가 먼저 말을 겁니다. **기본은 꺼져 있습니다.**

- **켜기/끄기**: `Ctrl+Alt+T`, 트레이 메뉴의 "먼저 말 걸기", 또는 말로 — `먼저 말 걸어줘` / `먼저 말 걸지 마`
- **간격 조절 (실행 중에 바로, 재시작 불필요)**
  - 트레이 메뉴 → **먼저 말 거는 간격 → 간격 직접 입력…**: 입력 상자가 뜹니다. **최소(분)** 과 **최대(분)** 를 직접 적고 Enter(또는 [적용]). 적용하면 먼저 말 걸기도 같이 켜집니다. 최대를 비우면 최소의 1.5배로 잡힙니다. 숫자 뒤에 단위도 쓸 수 있어요(`90`, `90분`, `1.5시간`). 범위는 최소 1~720분, 최대 최소~1440분이고, 잘못 쓰면 상자 안에 이유가 나옵니다. 현재 값은 같은 메뉴 맨 위에 표시되고, **지금 한 번 말 걸어보기**로 바로 시험해 볼 수 있습니다
  - 말로: `30분마다 먼저 말 걸어줘`, `1시간마다 먼저 말 걸어줘`, `더 자주 말 걸어줘`(간격을 절반으로), `덜 말 걸어줘`(두 배로)
  - 정한 시간 N분이면 N분~N×1.5분 사이의 무작위 시간이 지나면 말을 겁니다 (매번 똑같은 간격이면 부자연스러워서). 더 세밀한 조절(최소/최대를 따로, 조용한 시간대 등)은 `config.json` 의 `proactive`
- 사용자가 말하거나 입력하거나 마이크를 쓰면 **시간을 처음부터 다시 셉니다**. 그러니 대화 중에는 끼어들지 않습니다
- 말을 걸었는데 반응이 없으면 간격이 점점 늘어나고(1배, 2배, 3배), 3번 연속 무시되면 **사용자가 다시 말할 때까지 멈춥니다**
- 다음 경우에는 말을 걸지 않고 기다립니다: 캐릭터가 이미 말하는 중, 사용자가 **마이크로 말하는 중**(마이크가 켜져 있기만 한 것은 상관없음), 편집 모드/캡처/대화 목록을 쓰는 중, 입력창에 쓰던 글이 있음, 모델을 숨겨 둠, **자리를 비움**(키보드·마우스 입력이 10분 넘게 없음), 조용한 시간대. 조건이 풀리면(예: 자리로 돌아오면) 바로 말을 겁니다
- 서버가 처리에 실패해도(예: 무료 티어 한도) 화면에는 아무 오류도 띄우지 않고 서버 로그에만 남깁니다. 사용자가 요청하지 않은 말이라서입니다
- 먼저 건 말은 지금 대화(세션)에 이어집니다. 서버는 "마지막 대화로부터 N분이 지났다"는 걸 알고 말을 겁니다. 시스템이 보낸 지시문은 대화 기록 화면에는 보이지 않습니다

`config.json` (모두 생략 가능):

```json
"proactive": {
  "enabled": false,
  "minMinutes": 20, "maxMinutes": 45,
  "awayMinutes": 10,
  "maxUnanswered": 3,
  "onlyWhenVisible": true,
  "quietHours": ["23:00", "08:00"]
}
```

`awayMinutes: 0` 이면 자리비움 확인을 끄고, `quietHours` 는 지우면 시간대 제한이 없습니다 (자정을 넘겨도 됩니다). 단축키는 `hotkeys.toggleProactive` 로 바꿉니다.

## 시선 추적 (마우스 포인터 따라보기)

캐릭터가 마우스 포인터를 따라 **눈동자 → 고개 → 몸** 순서로 돌아봅니다. **기본은 켜져 있습니다.**

- **켜기/끄기**: `Ctrl+Alt+G` 또는 트레이 메뉴의 "시선 추적"
- 클릭 통과 중이어도, 포인터가 다른 모니터에 있어도 따라옵니다.
- 머리에서 포인터까지 **거리에 비례**해서 돌아봅니다. 가까우면 조금, `radius`(기본 400px) 이상 멀면 최대. 눈은 빠르게, 고개와 몸은 천천히 따라가서 자연스럽습니다.
- 포인터가 `idleSeconds`(기본 20초) 동안 안 움직이면 정면으로 돌아옵니다.
- 모션이 정한 값에 **더해서** 적용하므로 대기 모션/표정과 같이 동작합니다. 모델에 `ParamAngleX/Y/Z`, `ParamBodyAngleX`, `ParamEyeBallX/Y` 중 있는 것만 씁니다 (VTube Studio 모델 대부분 해당).

`config.json` (모두 생략 가능):

```json
"gaze": { "enabled": true, "radius": 400, "deadZone": 24, "strength": 1, "head": true, "idleSeconds": 20 }
```

| 키 | 설명 |
|---|---|
| `strength` | 0~1. 전체 움직임의 세기 (0.5 면 절반만 돌아봄) |
| `head` | `false` 면 눈동자만 움직이고 고개/몸은 고정 |
| `radius` | 이 거리(px) 이상 떨어지면 최대로 돌아봄. 작을수록 예민함 |
| `deadZone` | 머리 바로 근처(px)에서는 정면 |
| `idleSeconds` | 포인터가 멈춰 있으면 정면으로 돌아오는 시간. `0` 이면 계속 바라봄 |

## 대사창 끄기 / 화면 캡처 / 화면 공유

| 기능 | 단축키 (기본) | 설명 |

| 대사창 표시 on/off | Ctrl+Alt+B (메뉴: 대사창 표시) | 끄면 말풍선(대사/감정 태그)을 안 띄움. 음성·표정은 그대로. 캡처/오류 안내만 잠깐 표시 |

- 단축키 변경: `"hotkeys": {"capturePartial": "F8", "captureFull": "Shift+F8", "toggleScreenShare": "F10", "toggleBubble": "Ctrl+Alt+B"}`
- 화면 공유 모드에서 캡처/업로드가 실패하면 글자만 보냄. 설정은 `showBubble`, `screenShare` 로 저장됨

## 추가 기능 (마이크 / 일정 / 미디어)

### 1. 마이크 입력
- `Ctrl+Alt+M` 또는 트레이 메뉴의 "마이크 듣기"로 켜고 끕니다. **켜 두면 끌 때까지 계속 듣고**, 말이 끝날 때마다 글자로 바꿔 보냅니다. 앱을 켤 때는 항상 꺼져 있습니다.
- 켜져 있는 동안은 화면에 `🎤 마이크 켜짐` 표시가 나옵니다 (말하면 `듣는 중…`, 글자로 바꾸는 동안 `인식 중…`, 답을 기다리는 동안 `생각 중…`). 트레이 메뉴의 체크 표시도 실제 마이크 상태를 따라갑니다.
- 마이크는 **한 번에 한 말씩** 처리합니다. 말이 끝나 `인식 중…`으로 넘어가면 답을 기다리는 동안과 캐릭터가 말하는 동안(끝난 뒤 0.6초까지)은 새 마이크 입력을 받지 않습니다. 서버가 답을 못 보내도 2분 뒤에는 자동으로 풀립니다.
- **중단 버튼(⏹)**: 메시지 입력창 왼쪽에 있고, 답을 생각하거나 말하는 중일 때만 켜집니다(평소엔 흐림). 누르면 음성이 바로 멈추고, 서버도 답 만들기와 음성 만들기를 멈춥니다. 중단된 대화(내 질문과 답)는 대화 기록에 저장되지 않습니다. 서버가 예전 버전이면 음성만 멈춥니다. 서버를 같이 업데이트하세요.
- 캐릭터가 말하는 동안은 자기 목소리를 듣지 않습니다. 마이크를 켜면 말하던 음성은 끊깁니다. 스피커로 들으면 캐릭터 목소리가 마이크로 되돌아 들어갈 수 있으니 이어폰을 권합니다.
- **말 구간 감지는 Silero VAD** 로 합니다 (사람 목소리인지 판단하므로 키보드/TV 소리에 덜 반응). 모델이나 `onnxruntime-node` 가 없으면 예전 음량 방식으로 자동 전환하고 한 번 안내합니다. 설치는 아래 "음성 입력 (로컬 VAD / 화자 인증)" 참고.
- 오디오 처리는 **에코 제거(AEC)만** 켭니다. 노이즈 억제와 자동 이득은 꺼져 있습니다 (`mic.noiseSuppression` / `mic.autoGainControl` 로 켤 수 있음).
- 조용한 소리를 엉뚱한 문장으로 잘못 인식한 경우는 조용히 버립니다. STT 서버가 꺼져 있으면 오류 알림은 30초에 한 번만 보여줍니다.
- **음성 인식(STT)은 Project Miku 서버가 직접 합니다** (서버에 `pip install faster-whisper`, 설정은 서버 `config.yaml` 의 `stt:`). 클라이언트는 `serverUrl` 의 서버로 음성을 보내므로 따로 켤 서버도, 적을 주소도 없습니다. 다른 STT 서버(speaches, whisper.cpp server 등 OpenAI 호환 `/v1/audio/transcriptions`)를 쓰고 싶을 때만 `config.json` 의 `stt.url` 에 넣으세요.
- 인식된 문장은 키보드로 친 것과 똑같이 처리됩니다 (아래 로컬 명령도 음성으로 동작).
- Windows 설정 > 개인 정보 및 보안 > 마이크에서 "데스크톱 앱이 마이크에 액세스하도록 허용"이 켜져 있어야 합니다.

#### 음성 입력 (로컬 VAD / 화자 인증)

```
마이크 + PC 소리(기준) → 에코 제거(AEC) → Silero VAD → (선택) 화자 인증 → 서버의 STT(faster-whisper) → AI 응답
```

- VAD 와 화자 인증은 **메인 프로세스의 onnxruntime-node (CPU)** 에서 돌아갑니다. 둘 다 가벼워서 GPU 가 필요 없습니다. STT 는 서버가 하므로 CPU/GPU 선택은 서버 `config.yaml` 의 `stt.device` (auto 면 GPU 가 있으면 GPU)에서 합니다.
- 설치: 클라이언트 폴더에서 `npm install` 후 `npm run get-models` (Silero VAD 와 화자 모델을 `voice-models/` 에 받음. 화자 인증을 안 쓰면 `npm run get-models -- vad` 만).
- 모델이 없거나 불러오지 못하면 **죽지 않고** VAD 는 음량 방식으로, 화자 인증은 건너뛰고 그냥 동작합니다 (이유는 말풍선과 `miku.log` 에 남습니다).
- **화자 인증(선택)**: ① `config.json` 에 `"speaker": { "enabled": true }` ② 트레이 메뉴 > \"내 목소리 등록…\" 후 화면에 나오는 12개 문장을 하나씩 읽기 (음성 인식을 쓸 수 있으면 인식된 글자가 안내 문장과 많이 다를 때 다시 읽게 하고, 끝나면 내 목소리끼리의 점수가 나옵니다) → 이후 등록한 목소리와 다르면 조용히 무시합니다. 등록 전/모델 없음은 확인 없이 통과하고, 0.5초 미만의 짧은 말은 차단합니다(`shortPolicy` 가 `pass` 면 확인 없이 통과). \"등록한 목소리 지우기\" 로 삭제 (`speaker-profile.json`).
- **PC 소리 기준 에코 제거 (유튜브/음악을 스피커로 틀어 둔 채로 말하기)**: Windows 에서 PC 가 내는 모든 소리를 기준 신호로 받아(Electron loopback), 마이크에 섞여 들어온 만큼을 빼냅니다. 엔진은 **WebRTC AEC3** (`@ennuicastr/webrtcaec3.js`, WebAssembly) 이고 `renderer/aec3.js` 가 감싸고 있습니다. 기본으로 켜져 있고, AEC3 를 불러오지 못하거나 PC 소리를 못 받으면 앱 안의 소리만 지우는 브라우저 내장 방식으로 자동 전환하며 한 번 안내합니다. 끄려면 `config.json` 의 `mic.systemAec` 를 `false`.
  - 설치: 클라이언트 폴더에서 `npm install` (AEC3 는 `0.3.0` 으로 고정. 로더 파일명에 버전이 들어 있어서 버전을 올리면 `renderer/aec3.js` 의 `PKG_DIR` 도 같이 고쳐야 합니다).
  - 지연/울림 추정, 필터, 잔여 에코 억제는 모두 AEC3 가 알아서 합니다. 시뮬레이션에서 스피커 소리는 약 25dB 줄고 수렴도 몇 초 안에 끝납니다. 시스템 볼륨 변경, 스피커 왜곡에도 따라갑니다.
  - 한계: **스피커→마이크 지연이 약 0.5초를 넘으면 거의 못 지웁니다** (일부 블루투스 스피커). 이때는 헤드셋/유선 스피커를 쓰거나 `mic.systemAec` 를 끄세요. 스테레오는 합쳐서 하나로 다루고, 내가 스피커 소리와 동시에 말하면 목소리가 일부 깎일 수 있습니다 → 화자 인증을 같이 켜 두면 남은 소리가 대화로 넘어가는 것을 막아 줍니다. 헤드셋을 쓰면 가장 확실합니다.
  - 처리 결과는 입력보다 약 20ms 늦게 나옵니다 (AEC3 내부 버퍼). 말 구간 감지에는 영향이 없습니다. CPU 는 실시간 대비 약 5% 입니다.
  - 세부 조정은 `mic.aec` (`rate`: AEC3 내부 처리 속도 `48000`(기본) 또는 `32000`).

### 2. 일정 알림
말이나 글로 등록합니다. 문장 끝이 "알려줘/깨워줘/알림"이고 시각이 있어야 인식합니다.
- `30분 뒤에 빨래 널라고 알려줘`, `10분 타이머`
- `내일 오전 7시에 깨워줘`, `오늘 저녁 8시 30분에 운동 알려줘`, `10월 30일 오후 3시에 시험 알려줘`
- `매일 아침 8시에 약 먹으라고 알려줘`, `평일 오전 9시에 출근 알려줘`, `매주 금요일 오후 5시에 주간보고 알려줘`
- 오전/오후를 말하지 않으면 가장 가까운 미래 시각으로 잡습니다.
- 확인/취소: `/일정`, `/알림 취소 2`, `/알림 전체 취소`
- 일정은 `schedules.json` 에 저장됩니다. 시각이 되면 알림음과 말풍선이 나오고 서버로도 보내 캐릭터 목소리로 말합니다 (`schedule.speakViaServer`). 모델을 숨긴 상태면 시스템 알림이 뜹니다.

### 4. 미디어 / 볼륨 (Windows)
문장 전체가 명령일 때만 인식합니다.
- `다음 곡`, `이전 곡`, `재생`, `일시정지`, `지금 무슨 곡이야`
- `볼륨 50으로 해줘`, `볼륨 올려`, `볼륨 20 올려줘`, `소리 줄여`, `볼륨 최대`, `볼륨 몇이야`, `음소거`, `음소거 해제`
- 음악 멈추기는 `음악 꺼줘`, `노래 멈춰줘`, `노래 그만`, `그만 틀어줘`, `음악 정지해줘`, `일시중지`처럼 말해도 되고, `히요리야 음악 멈춰줘`처럼 캐릭터를 부르며 말해도 됩니다 (뒤에 명령 낱말이 이어질 때만 부름말로 봅니다). `소리 조금 줄여줘`, `음악 소리 줄여줘`, `음소거 풀어줘`, `소리 다시 켜줘`도 됩니다. 대화로 한 말("음악 꺼진 줄 알았어", "노래 그만 불러줘")은 명령으로 보지 않습니다.
- 일시정지는 재생 중인 미디어를 **모두** 찾아 멈춥니다 (브라우저 탭 여러 개 등에서 "현재" 세션이 멈춰 있는 것이어도 실제로 재생 중인 것을 멈춤). 아무것도 재생 중이 아니면 "이미 멈춰 있어요"라고 알려 주고, Windows 가 재생 정보를 주지 않는 플레이어에는 재생/일시정지 키를 누릅니다.
- 볼륨은 Windows 마스터 볼륨(Core Audio)을 직접 설정합니다.


## 설정 창 / 장기 기억 / 스트리밍

- **설정 창**: 트레이 > "설정…" 또는 대화 목록의 **⚙**. 탭 3개: **모델**(지금 모델의 persona / 감정 태그↔표정 / 음성 — 모델 폴더에 저장), **화면/앱**(`config.json` 에 저장: 서버 주소, 모델 크기, 말풍선, 먼저 말 걸기, 시선…), **기억**. 서버 설정(LLM, 음성, GPT-SoVITS, 음성 인식 등)은 이 창이 아니라 **통합 런처**(`Project_Miku_launcher`)의 "서버 설정" 탭에서 서버의 `config.yaml` 로 고칩니다. ↻ 표시 항목은 다시 켜야 적용됩니다 (화면/앱 탭에는 "지금 다시 시작" 버튼이 나옵니다). 제목줄("설정")을 마우스로 끌어 창을 옮길 수 있습니다 (화면 밖으로는 나가지 않음).
- **기억 탭**: 캐릭터가 대화에서 알아낸 사실을 보고(✎ 고치기, 🗑 지우기: 두 번 눌러 확인), 직접 추가하고, 전체 지울 수 있습니다. 기억 추출/대화 요약은 서버가 알아서 합니다 (서버 README 참고).
- **스트리밍**: 답이 만들어지는 동안 말풍선에 글자가 이어서 나타나고, 표정이 먼저 바뀌며, 음성은 문장이 끝나는 대로 먼저 재생됩니다. 끄려면 설정 창의 "답을 만드는 대로 먼저 보여주기" 또는 `config.json` 의 `"streaming": false`.
- **웹 검색**: 서버에 `pip install -U ddgs` 를 설치하면 날씨/뉴스/최신 정보를 물을 때 서버가 DuckDuckGo 로 검색해서 답합니다. 검색하는 동안 말풍선에 `🔍 "검색어" 검색 중…` 이 보입니다. 켜고 끄기/결과 개수는 통합 런처의 "서버 설정" 탭 "검색" 항목.

### 설정 (config.json)

모두 생략 가능합니다 (마이크의 음성 인식은 `serverUrl` 의 서버가 합니다).

```json
"mic":      { "vadThreshold": 0.5, "vadSilenceMs": 800, "maxSeconds": 30 },
"vad":      { "model": "voice-models/silero_vad.onnx" },
"speaker":  { "enabled": false, "model": "voice-models/speaker.onnx", "threshold": 0.5, "minSeconds": 0.5, "shortPolicy": "reject" },
"stt":      { "url": "", "language": "ko", "timeout": 120 },
"schedule": { "speakViaServer": true, "chime": true }
```

`stt.url` 은 비워 두면 서버(`serverUrl`)를 쓰고, 다른 STT 서버를 쓸 때만 적습니다 (`model`, `apiKey`, `prompt` 도 그 경우에만). `mic` 의 `systemAec`(PC 소리 기준 에코 제거, 기본 true), `vadThreshold`(말소리로 볼 확률, 기본 0.5), `vadSilenceMs`(이만큼 조용하면 문장 끝, 기본 800), Silero 를 못 쓸 때의 예전 방식 값 `threshold`/`silenceMs`, `echoCancellation`/`noiseSuppression`/`autoGainControl` 은 생략하면 기본값입니다. `speaker.threshold` 는 높일수록 엄격하고(오탐 감소, 내 말도 막힐 수 있음), `minSeconds`(기본 0.5)보다 짧은 말은 `shortPolicy` 가 `reject`(기본)면 차단하고 `pass` 면 확인 없이 통과시킵니다. `mic.vadMinUtteranceMs`(기본 500)보다 짧은 말소리는 인식하지 않습니다.

단축키는 `hotkeys.toggleMic` (기본 `Ctrl+Alt+M`) 로 바꿀 수 있습니다. 이 기능들은 로컬에서 처리되므로 대화(세션) 기록에는 남지 않습니다. 일정 알림은 서버로 보내져 지금 대화에 기록됩니다.

테스트: `node test/commands.test.mjs` (명령 해석기), `node test/sessions.test.mjs` (대화 패널), `node test/proactive.test.mjs` (먼저 말 걸기 타이머), `node test/proactive-config.test.mjs` (설정 검증), `node test/interval.test.mjs` (간격 직접 입력), `node test/gaze.test.mjs` (시선 추적), `node test/mic.test.mjs` (마이크: 음량 방식), `node test/vad.test.mjs` (마이크: Silero 방식, VAD/화자 인증 모듈), `node test/aec.test.mjs` (에코 제거 시뮬레이션 + 마이크 연결), `node test/aec-frames.test.mjs` (AEC3 에 10ms 단위로 번갈아 넣는지, 가짜 모듈로 확인), `node test/stt-route.test.mjs` (STT 주소/전송 경로), `node test/glue.test.mjs` (app.js 의 입력/알림/일정/마이크/설정 변경 연결부), `node test/stream.test.mjs` (스트리밍 상태/서버 메시지 변환), `node test/events.test.mjs` (서버 이벤트에 대한 화면 반응), `node test/settings.test.mjs` (설정 창), `node test/profile.test.mjs` (모델별 persona/감정 태그), `node test/bubble.test.mjs` (마우스를 올리면 대사창 다시 보이기)

## 음성이 중간에 끊길 때 (진단)

스트리밍 TTS 가 만든 WAV 는 헤더 길이가 0/잘못된 값인 경우가 있어, 클라이언트가 자동 보정합니다. 그래도 끊기면 `miku.log` 의 `[audio]` 줄을 확인하세요.

- `[audio] 수신 … url` : 받은 파일 크기/보정 내용/주소. 이 주소를 브라우저에 붙여 넣어 재생해 보면 **서버가 만든 파일 자체가 끊겼는지** 구분됨
- `[audio] 재생 시작/재생 끝 a / b` : 실제 재생 시간(a)과 음성 길이(b). a < b 이면 클라이언트 경고가 함께 기록됨

## 서버 연결

Project Miku 서버(`Ui/ws_server.py`) 프로토콜에 맞춰져 있습니다.

- 접속: `config.json` 의 `serverUrl` (예: `ws://127.0.0.1:8000/ws`). `client_id` 는 자동으로 붙습니다.
- 송신: `{"op":"chat","data":{"text":..., "think":false}}`
- 수신: `chat_result` / `observe_result` / `notification_result` 의 `llm_response`, `emotion`, `audio_url`
  (`should_speak:false` 이면 무시). 오디오는 WebSocket 이 아니라 `audio_url` 을 HTTP 로 받아 재생합니다.
- 하트비트: 서버의 `server_ping` 에 `client_pong` 으로 응답 (60초 무응답 시 서버가 연결을 끊음)

선택 설정 (`config.json` 에 추가):

| 키 | 설명 |
|---|---|
| `audioBaseUrl` | 서버가 알려주는 `audio_url` 호스트가 안 맞을 때 덮어쓰기 (예: `http://127.0.0.1:9880`) |
| `emotionAliases` | (옛 방식) 서버 감정 라벨 -> 표정 이름. 이제는 모델 폴더의 `emotionAliases.json` 을 쓰고, 이 값은 그 파일이 처음 만들어질 때만 옮겨 담김 |

서버 감정 라벨 목록은 `analyze_emotion` 구현에 달려 있습니다. 매핑이 없는 라벨은 개발자 콘솔에
`[emotion] 매핑 없음: "..."` 으로 찍히니, 그 값을 `emotionAliases` 에 추가하세요.
프로토콜이 바뀌면 `renderer/ws-client.js` 의 `adapt()` / `encodeChat()` 만 고치면 됩니다.

## 알려진 한계

- 클릭 통과 판정은 모델의 바운딩 박스 기준 (픽셀 단위 판정 아님)
- VTS 전용 기능(아이템, 트래킹 파라미터 설정, 물리 배율)은 반영하지 않음
- 음성 재생 중 가끔 '톡' 하는 팝노이즈는 오디오 버퍼를 넉넉히 잡아(기본 `playback`) 줄였어요. 런처 설정 > 음성 > "오디오 버퍼" 에서 `0.2` 처럼 초 단위로 키울 수 있어요 (`config.json` 의 `audioLatency` 를 런처가 대신 고쳐요. 클라이언트를 다시 시작해야 적용). 클수록 안정적이고 입 모양이 늦어져요. 입 모양이 늦게 느껴지면 `balanced`/`interactive` 로 낮추세요
- 립싱크는 WebAudio 로 재생하면서 음량을 읽어 입 파라미터(model3.json 의 LipSync 그룹, 없으면 `ParamMouthOpenY`)에 직접 넣음. 입이 작게 벌어지면 `config.json` 에 `"lipSyncGain": 8` 처럼 올리세요 (기본 5)

## 실시간 가사 (Windows)

스포티파이/유튜브 등이 윈도우 미디어 제어에 알리는 곡 정보(제목/가수/길이/재생 위치)를 계속 읽어서 가사를 찾고, **말풍선 자리**에 띄웁니다. 알송 가사에 같은 시각의 줄(발음, 번역)이 같이 들어 있으면 원문 / 발음 / 번역 3줄, 없으면 원문 / 다음 줄 2줄이에요 (아랫줄은 흐리게). 모델이 노래하듯 입도 움직입니다.

- **가사 출처**: 알송(1순위) → LRCLIB(보조). 알송은 비공식 서버라 막히거나 바뀔 수 있어요. 개인 사용 범위로만 쓰세요.
- **검색어 보정**: 유튜브 제목의 `(Official MV)`, `- Topic`, `feat.` 등을 떼고 `가수 - 제목` 순서를 바꿔 가며 찾습니다. 그래도 없으면 서버 LLM 으로 제목/가수를 정리(로마자 → 원문, 한국어 표기 등)해서 다시 찾아요 (곡마다 한 번, 서버에 저장). 음악이 아닌 영상은 가사를 띄우지 않습니다. 서버 쪽은 `POST /lyrics/normalize` (서버 `lyrics_query.py`).
- **말풍선과 겹칠 때**: 말풍선이 우선이라 가사는 잠깐 숨고, 음성(TTS)이 끝나면 **1초 뒤** 말풍선이 사라지며 가사로 돌아옵니다.
- **입모양**: 음성이 나오는 동안은 항상 음성(TTS)이 우선이고, 음성이 없을 때만 가사 박자에 맞춰 입이 움직여요.
- **캐시**: `lyrics-cache/` (가사와 곡별 싱크 보정). 지우면 다시 찾습니다.

### 조작
| 조작 | 내용 |
|---|---|
| `Ctrl+Alt+L` | 가사 켜기/끄기 |
| `Ctrl+Alt+PageUp` / `PageDown` | 싱크 +0.5초(가사가 더 일찍) / -0.5초 · `Ctrl+Alt+End` 초기화 (곡별로 저장) |
| `/가사` | 지금 곡, 출처, 싱크 보정 보기 |
| `/가사 다시` | 다시 찾기 |
| `/가사 가수 - 제목` | 그 검색어로 직접 찾기 (자동 보정 없음, 결과는 지금 곡으로 저장) |
| `/가사 +0.5` `/가사 -0.5` `/가사 0` | 싱크 보정 / 초기화 |
| `/가사 끄기` `/가사 켜기` | 켜기/끄기 |

설정 창 > 화면/앱 > "가사"에서 켜기, 노래 입모양과 그 속도, LLM 보정, 출처, 대상 앱(예: `spotify, chrome`), 줄 구성(auto/next), 아랫줄 투명도, 배경을 바꿉니다. 가사 글자 크기는 대사창과 따로, 편집 모드(트레이 > 편집 모드)에서 1줄/2줄/3줄 슬라이더로 줄마다 맞춰요 (편집 중에는 가사 견본이 보여요). 가사가 나오는 동안에는 "먼저 말 걸기"가 끼어들지 않아요. 브라우저가 재생 위치를 갑자기 0초로 알리면(가끔 그래요) 무시하고 계속 따라가며, 그런 일은 `miku.log` 에 `재생 위치가 튀었어요` 로 남아요 (직접 맨 앞으로 되감았다면 일시정지 후 재생하면 맞아요). `config.json` 의 `lyrics` 항목이에요.
